# 训练追踪 App — 需求与数据规格 v1.2

导出日期：2026-10-23（v1.1：确定 PWA 路线；休息计时器改为组间秒表，不做锁屏通知；增加开发流程约定。v1.2：明确数据只存本机、两个用户完全独立、不做同步）。配套数据文件：`training-plan.json`（训练计划、每周安排、规则、过渡周）。

## 0. 一句话

一个手机上的训练清单 + 组间秒表：打开就看到今天练什么、几组、每组几次；训练时点选动作、点"完成一组"，秒表自动开始显示这一组做完后已经休息了多久；做完的动作变灰，避免重复。

## 0.1 开发流程约定（给 Claude Code 的工作方式，也放进 CLAUDE.md）

目的：避免一次会话做太多、中途撞到用量上限（usage limit）把工作丢掉。

1. **小步前进，每步可验证。** 一次只做一个功能点（例如"首页按星期显示今天的安排"），做完立刻在浏览器里跑一遍验收项，通过了再做下一个。不要一口气实现整个 Phase。
2. **每个通过的步骤立刻 git commit。** 提交信息写清楚做了什么、验收了什么。仓库在第一步就 `git init`，第一次提交就包含 spec、JSON 和 CLAUDE.md。
3. **维护 `PROGRESS.md`。** 每完成一步追加一行：日期、做了什么、下一步是什么、已知问题。会话被中断（用量上限、断网、关机）后，新会话第一件事是读 `PROGRESS.md` 和 `git log`，从"下一步"继续，不重做已完成的部分。
4. **先写骨架再填内容。** 新文件先建最小可运行版本并提交，再逐步加功能；避免一个几百行的文件写到一半中断。
5. **测试独立于实现。** 每个 Phase 的验收项写成可以单独执行的检查清单（见第 5 节），一步一验，不攒到最后。
6. **不做计划外的功能。** 规格之外的想法先记到 `PROGRESS.md` 的"以后再说"，不在当前步骤里实现。

## 1. 用户与平台

- 用户：本人（iPhone）；之后太太（iPhone）。**两个人的数据完全独立，不共享、不同步**：她打开同一个链接、添加到主屏幕，就得到一份只存在她手机上的独立副本，各自的计划和记录互不可见。没有账号、没有登录、没有服务器。
- **路线：PWA（已确定）**。网页 App，Safari "添加到主屏幕"，部署到 GitHub Pages 或任何静态托管。离线可用，数据存本机；太太只需打开链接再添加到主屏幕。
- 开发机：MacBook（用 Claude Code）或 Windows PC 都可以，PWA 不依赖 Xcode。
- 技术选型由实现者定，但要求：纯前端、无后端、单页应用、构建产物是静态文件；依赖越少越好。
- 以后如果需要锁屏通知再考虑移植原生（SwiftUI），数据模型和 `training-plan.json` 不变。本版不做通知。
- 语言：中文界面。重量单位 lb（健身房是磅片），设置里可切 kg 显示。

## 2. 数据模型

与 `training-plan.json` 对应。所有 id 用英文 slug，名称用中文。

### 2.1 Program（训练计划，静态配置，可编辑）

- `dayTemplates[]`：训练日模板（推日 / 拉日 / 腿日 / 上肢B+二区）
  - `id`, `name`, `type`（strength | cardio | strength+cardio）, `enabled`（上肢B 初始为 false）
  - `exercises[]`：见 2.2
  - `cardio`（可选）：力量后接的有氧段
- `cardioTemplates[]`：独立的有氧/球/散步模板
- `weeklySchedule[]`：周一到周日 7 条，每条有 `primary`（固定训练日 / 可选打球 / 休息）和 `fallback`（不打球时做什么）
- `rules[]`：排程规则，首页以提示形式展示；只有"一周最多 3 次球"做软校验（超了给警告，不阻止）
- `overrides[]`：按日期覆盖当天安排（过渡周就是用这个表达的；以后临时调课也用它）
- `defaults`：自动开始休息、默认休息秒数、进阶规则

### 2.2 Exercise（动作）

| 字段 | 说明 |
|---|---|
| `id`, `name`, `muscle` | 标识、显示名、肌群 |
| `load` | `{value, unit}`；`value: null` = 第一次做时让用户填。特殊标记：`bodyweight: true`（自重）、`assisted: true`（引体助力，数值越小越难，进阶方向是减）、`perSideLoad: true`（器械"每边"配重）；`label` 是显示用的原文，如 "120 每边"、"37.5 助力" |
| `perSide` | true = 每侧各做一组（单臂划船、弓步走），计数时一组 = 左右各一次 |
| `sets` | `{min, max}`；目标组数 = max；做满 min 组后允许手动"结束动作" |
| `reps` | `{min, max}` 次数区间 |
| `restSeconds` | 这个动作的参考休息秒数（覆盖默认值）；秒表到达这个值时变色提示，不强制 |
| `alternates[]` | 替代动作列表 `{name, load?}`；选用后当次记录以替代动作名保存 |
| `notes` | 执行提示（顶端停 1 秒、打球周减量等） |

### 2.3 WorkoutSession（一次训练的记录）

```
{
  id, date, templateId | cardioId,
  startedAt, finishedAt,
  activityKind: "strength" | "cardio" | "ball" | "rest",
  entries: [
    {
      exerciseId, usedAlternate?: string,
      sets: [ { setNo, weight, reps, side?: "L"|"R", completedAt, restTakenSeconds } ],
      status: "done" | "partial" | "skipped"
    }
  ],
  cardio?: { minutes, avgHr?, note? },
  note?
}
```

### 2.4 Settings

`unit`（lb/kg 显示）、`autoStartRest`（完成一组后自动开始秒表，默认开）、`defaultRestSeconds`（参考休息时长）、`keepScreenAwake`（训练模式下屏幕常亮，默认关，耗电）、`sound`（到达参考时长时响一声，默认关）。

### 2.5 存储（数据在哪里）

- **所有数据只存在手机本地**：训练计划、每次训练记录、设置，全部写在这个主屏幕 Web App 自己的浏览器存储里（IndexedDB）。GitHub Pages 只负责分发代码（HTML/JS），不接收也不保存任何用户数据；App 运行时不发任何网络请求（除了更新自身代码）。
- iOS 上"添加到主屏幕"的 Web App 有独立于 Safari 的存储容器：在 Safari 里打开同一个网址看到的是另一份空数据，这是正常现象，不是 bug。两台手机之间天然隔离，不需要任何多用户逻辑。
- 用 IndexedDB，不用 localStorage（容量小、同步阻塞）。数据量很小（一年的记录也只有几百 KB），不用担心配额。
- **会丢数据的情况**，要在设置页里明示：从主屏幕删除这个 App、在 Safari 设置里"清除历史记录与网站数据"、换手机。iOS 对主屏幕 Web App 不执行 7 天未用即清除存储的策略，但系统存储极度紧张时仍可能清理。支持的话启动时调用 `navigator.storage.persist()` 申请持久存储。
- **备份 = 导出 JSON**：整个数据库导出成一个 JSON 文件，通过系统分享菜单存到"文件"/iCloud Drive 或发给自己；导入时可"覆盖"或"合并"。换手机就是导出再导入。App 每完成 10 次训练提醒一次备份。
- 首次启动：选择"载入内置计划（training-plan.json）"或"从空白计划开始"。太太的手机选空白或载入后自行修改，和本人的数据没有任何关系。

## 3. 页面与流程

### 3.1 今日（首页）

- 顶部：今天星期几、按 `overrides` → `weeklySchedule` 决定的安排。
- 固定训练日：显示模板名和动作清单预览（动作 · 重量 · 组数×次数），按钮"开始训练"。
- 可选打球日：两个按钮——"今天打球"（记一条 ball 记录，可填时长 / 平均心率 / Zone3+ 分钟）和"不打，做二区"（进入有氧记录）。
- 休息日：显示"休息 / 散步"，可选记一条散步。
- 底部：本周 7 天小条，已完成的打勾；规则提示折叠显示；本周球次数计数（≥3 次时变色警告）。
- 上肢B 未启用时，周四显示二区；设置里有开关"启用上肢B"。

### 3.2 训练模式（核心页面）

- 动作列表，每行：名称、重量（含 label）、`已完成组数 / 目标组数`、次数区间。
- 状态：`待做`（正常）/ `进行中`（高亮，只能有一个）/ `完成`（灰掉、打勾、列表里下沉到底部）。
- 点一行 → 变成进行中；展开显示：
  - 上次训练这个动作的每组数据（重量 × 次数），作为参考
  - 本次重量输入框（预填上次的值，没有历史就预填计划值；`null` 则必填）
  - 次数输入（预填上次同组数，或区间上限）
  - 大按钮 **完成一组**
  - 次要按钮：换替代动作（弹出 `alternates`）、跳过这个动作、结束动作（已达 min 组时可用）
- 按"完成一组"：
  1. 记录一组（重量、次数、时间戳）
  2. 已完成组数 +1；`perSide` 动作按左→右各一次算一组
  3. `autoStartRest` 开启时组间秒表立即从 0 开始计时（参考值 = 动作的 `restSeconds`）
  4. 已完成组数 = 目标组数 → 动作标记完成、变灰、下沉；进行中状态清空
- 防重复：完成的动作点击无反应，只有"撤销最后一组"和"再加一组"两个明确入口。
- 撤销：撤销最后一组会把动作从完成态拉回进行中。
- 结束训练：汇总（总组数、总时长、每个动作的最佳组）、保存。中途退出要自动保存草稿，再打开能续。

### 3.3 组间秒表（不做倒计时、不做通知）

- 页面顶部固定一条，大号数字显示"上一组完成后已经过了多久"（正计时，mm:ss），旁边小字显示参考休息时长（如 `02:30`）。
- 到达参考时长：数字变色（例如从灰变绿），可选响一声（设置里默认关）。不弹通知、不震动、不强制结束。
- 按钮只有一个：**重置**（偶尔需要手动重开）。点下一次"完成一组"时秒表自动归零重新开始。
- 秒表期间仍可滚动查看、点选其他动作。
- 锁屏 / 切到别的 App 再回来，秒表显示的仍然是真实经过的时间。
- **实现要点（iOS 的坑）：**
  - 不要用 `setInterval` 累加秒数。只记录 `lastSetCompletedAt` 时间戳，每次渲染用 `now - lastSetCompletedAt` 算显示值；页面从后台回到前台（`visibilitychange`）时立刻重算一次。这样锁屏期间 JS 被挂起也不会算错，而且几乎不耗电。
  - 时间戳同时写进本次训练的草稿存储，刷新页面或 App 被系统杀掉后重新打开，秒表还能接着算。
  - 屏幕常亮（Screen Wake Lock API）作为可选开关，默认关——常亮一小时会明显耗电；因为秒表基于时间戳，锁屏不影响正确性，所以默认让屏幕正常锁定。
  - 声音如果做：必须在用户点击"完成一组"的手势里预先解锁音频；静音键打开时可能无声，所以只当作辅助。
  - `navigator.vibrate` 在 iOS Safari 不支持；Web Push 需要服务器；本版都不做。

### 3.4 历史 / 进步

- 按日期的训练列表（类型、时长、总组数）。
- 点进去看每组数据；每个动作的历史折线（最佳组的重量、总次数）。
- 进阶提示：某动作连续两次训练所有组都到 `reps.max` → 在训练模式里提示"可以加重 +5 lb"（腿部器械 +10，引体助力 −5）。只提示，不自动改计划。
- 退阶提示：连续两次训练次数低于 `reps.min` → 提示"下次减一组"。

### 3.5 计划编辑

- 编辑动作：名称、重量、组数区间、次数区间、休息秒数、替代动作、备注；排序拖动；新增 / 删除。
- 编辑每周安排和 overrides（按日期调课）。
- 启用 / 停用上肢B。
- 任何编辑不影响已保存的历史记录。

### 3.6 设置

单位、自动休息开关、默认休息秒数、声音、屏幕常亮、导出 / 导入 JSON、清空数据（二次确认）。

## 4. 非功能需求

- 离线完全可用（Service Worker 缓存整个 App）。
- 首屏 1 秒内可操作；训练模式单手操作，主按钮 ≥ 56 px 高。
- 数据只存本机；不收集任何东西；导出的 JSON 可读、可手改。
- 深色模式跟随系统。
- 训练模式下误触保护：返回 / 关闭前确认。

## 5. 分阶段开发与验收

每个阶段单独能跑、单独验收，再进下一阶段。

**Phase 1 — 看计划 + 练（核心）**
- 读取 `training-plan.json`，首页按星期和 overrides 显示今天的安排 ✔ 验收：改手机日期到 10/24、10/27、11/2 各看一次，显示拉日 / 可选打球 / 拉日
- 训练模式：选动作、完成一组、计数、完成后变灰、撤销 ✔ 验收：把推日 5 个动作全部做完，列表全灰，撤销一组后恢复
- 组间秒表：完成一组后自动从 0 开始，到参考时长变色，重置按钮 ✔ 验收：完成一组后锁屏 2 分钟再解锁，秒表显示约 02:00；切到别的 App 再回来数值正确；刷新页面后秒表继续
- 本机保存本次训练（草稿自动保存）✔ 验收：训练中途关掉 App 再打开，已完成的组还在
- 每完成一项提交一次 git，并更新 `PROGRESS.md`

**Phase 2 — 记录与进步**
- 每组重量 / 次数输入、上次数据预填、历史列表、动作折线、进阶 / 退阶提示 ✔ 验收：连续两次把斜上卧推全部做到 10 次，第三次打开出现"+5 lb"提示

**Phase 3 — 计划编辑 + 排程**
- 动作编辑、每周安排编辑、overrides、启用上肢B、打球日记录、本周球次数警告 ✔ 验收：把周二改成固定二区，首页随之变化；记 4 次球，首页出现警告

**Phase 4 — 备份与第二台手机**
- 导出 / 导入 JSON（覆盖 / 合并）、备份提醒、首次启动的"内置计划 / 空白计划"选择 ✔ 验收：导出后删除 App 再重装、导入，历史和计划完整恢复；第二台手机安装后历史为空、看不到第一台的任何数据
- 不做同步、不做账号。

## 6. 开放问题

1. 要不要记有氧的心率数据（手动填 Apple Watch 的平均心率和 Zone3+ 时间）？影响 ball / cardio 记录的字段。
2. 秒表到参考时长的提示音要不要做？默认关，可以留到 Phase 2 再决定。
